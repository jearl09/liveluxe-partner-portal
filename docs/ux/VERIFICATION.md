# Phase 3 verification (brief §12.4)

Run on 14 Oct 2026 against the local dev server (functional and axe checks) and a local production build
(Lighthouse). Test accounts: the demo partner administrator and the ops test user, which was raised to Live Luxe
administrator only for the Partners and Rate cards routes and put back afterwards. Nothing was submitted, approved or
declined during these checks.

**Result: 22 of the 24 checklist items pass. Two pass in part, and the gaps are logged:** the rate card has no live
preview (NEEDS_BACKEND #8), and four of the ten §9.2 next steps need data or endpoints (NEEDS_BACKEND #10).

## Found and fixed in this phase

1. **Search lost prices on long stays.** See the Search row above. This was a real bug for the product's main use
   case (30+ night placements).
2. **Cover photos could go missing.** Search read every photo row, up to 1,000 of 2,336, to find one cover per
   listing. It now reads only the first photo of each listing.
3. **Accessibility:** the password field's name, an unsupported ARIA attribute on the date pickers, the account
   menu keyboard trap, and the 90-stop calendar.
4. **Dead links:** Partners and Rate cards were in the ops navigation for roles those pages turn away.
5. **Wording:** credit-limit errors told partners to "raise the credit limit on the partner's page" (an ops
   instruction), and a price-hash mismatch said "Quote integrity check failed". Partners now get the §9.2 wording,
   and a suspended organisation sees a banner on every page.
6. **Print and the gold-primary rule,** as above.
